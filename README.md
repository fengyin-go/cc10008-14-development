# 交互式数据分析工作台

离线版交互式数据分析工具，涵盖多源接入、查询分析、可视化图表、报告生成、异常检测与数据服务编排，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/`（`index.tsx` 再导出同名视图），页面只负责渲染，
  读写统一走 `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `interactive-analytics-lab:entries` 这一项，或调用 `resetModule(模块)`。
- 调度管理的计划、配置版本与运行状态在 `frontend/src/lib/scheduler.ts`，表达式解析与时区换算在
  `frontend/src/lib/cron.ts`，单测见 `frontend/tests/scheduler.test.ts`（`npm test`）。

## 调度管理

调度配置关联的是周任务，前置任务、最大并发数与超时终止都参与计划生成，不再让人凭表达式猜执行时间。

- **计划生成**：按 `调度表达式` + `时区设定` 展开未来 7 天的执行批次（标准 5 字段 cron，触发时刻按
  配置时区解释，跨日与夏令时都换算成绝对时间），每批带配置快照与版本号，按批次编号排序。
- **保存阶段校验**：表达式无未来触发时间、最大并发数为 0、超时终止短于 60 秒检查周期、时区不可识别、
  前置任务不存在等问题在保存时就逐条列出，不会留到运行时才暴露。
- **并发与前置**：启动批次受最大并发数约束；上游任务未完成时保持排队，上游被停用或已失败时转为
  「阻塞」，不会静默跳过后面的节点。
- **超时**：检查超时只把当前批次标为「已超时」并记录失败区间，下一批仍保持排队；失败区间可一键交给
  分析流水线（生成待调度的回放节点）。
- **版本裁决**：两个编辑窗口同时保存时只有一个版本生效，另一个会显示被哪个版本裁决；已启动批次冻结
  执行凭据与快照，之后改配置只影响下一批次。
- **取消与恢复**：取消调度后可选择保留排队批次继续跑（来源标为「取消后续跑」），或一并作废；恢复调度
  只从恢复时刻往后排，不补造停机期间错过的批次。
- **分页**：计划页按批次编号排序分页，每页只带当前配置的批次，不混入其它过滤结果。
